## Оставшиеся ошибки

### 1. [P1] Старые кэши индекса ломают запуск после обновления

`src/aevum/data/librispeech.py:222-225`.

Предыдущая версия сохраняла JSON-массив пар, новая вызывает cached.get()
без проверки типа. При существующем segment_index_...json процесс падает
с AttributeError: 'list' object has no attribute 'get', не доходя до ветки
«stale, rebuilding». Воспроизведено настоящим __init__ с подменёнными
metadata/resampler и реальным старым JSON `[[0,0]]`.

Сначала проверять isinstance(cached, dict). Старые массивы и повреждённый
JSON считать инвалидным кэшем и перестраивать. Не требовать ручного удаления
датасета ради миграции индекса.

### 2. [P1] GPU --resume переносит CPU RNG state на CUDA

`scripts/train_stage1.py:242,262-265`.

torch.load(..., map_location=device) загружает все тензоры на CUDA при
обычном GPU-запуске, включая rng_state['torch']. Затем torch.set_rng_state
ожидает CPU ByteTensor. Поэтому восстановление собственного нового
checkpoint на GPU упирается в неверный тип/устройство RNG state.

Загружать checkpoint на CPU, затем load_state_dict модели/оптимизатора,
либо явно возвращать RNG byte tensors на CPU перед восстановлением.
Проверить save→resume на CUDA до длинного запуска.

Это вывод из кода и API-контракта, а не локально воспроизведённый GPU crash.
Источники: [torch.load](https://docs.pytorch.org/docs/2.14/generated/torch.load.html)
и [torch.set_rng_state](https://docs.pytorch.org/docs/2.14/generated/torch.set_rng_state.html).

### 3. [P1] Gate-fusion всё ещё противоположный в диагностике и production

`scripts/diagnose_decoder_output_gain.py:276-277` и
`src/aevum/models/decoder.py:105-106`.

step_branches теперь правильно отделяет чистые temporal/skip, но формула
диагностики осталась `skip + gate_decoder*temporal`. Production всё ещё
`temporal + skip_gate*skip`. При одинаковом g=0.05 меняется ослабляемая
ветка. Выделить общие слагаемые недостаточно, чтобы унифицировать fusion.

Нужна общая функция fusion, используемая обоими путями, и проверка равенства
при одинаковых весах, input, state и коэффициентах. Если обратный gate
нужен как отдельная ablation, явно называть её другой архитектурой и
иметь baseline, совпадающий с production.

### 4. [P1] Непроверенная директория получает «проверенный» marker

`src/aevum/data/librispeech.py:113-115,132-142`.

При существующей директории без архива код даже с download=True доверяет
ей и записывает marker с verified=False. Следующий вызов проверяет только
marker.exists(), печатает «extraction verified complete» и возвращается.
Это воспроизведено на пустой директории двумя последовательными вызовами.

Не создавать completion marker для непроверенного корпуса. Читать и
валидировать содержимое marker и наличие split; при download=True получать
архив/manifest для проверки. Разрешённый режим непроверенного локального
корпуса должен быть явным и не превращаться в verified при следующем запуске.

### 5. [P2] Диагностики продолжают оптимизировать старый misaligned loss

`scripts/overfit_full_pipeline_v4.py:128`,
`scripts/diagnose_decoder_output_gain.py:249`,
`scripts/sanity_overfit.py:74`; default ReconstructionLoss.delay=0.

Только train_stage1.py передаёт delay=240. Значит, короткий sanity/overfit
с causal frontend всё ещё решает задачу предсказания ненаблюдавшихся
сэмплов, а основной запуск — уже другую задачу. Результаты нельзя считать
проверкой нового train-пайплайна.

Добавить одинаковый явный alignment параметр/конфигурацию в актуальные
диагностики; оставить delay=0 как подписанную A/B-ветку. Не менять слепо
все generator-only/free-latent опыты: у них другая постановка. WAV панели
тоже пока сохраняются без выравнивания; для A/B нужны aligned-пары и
документированная обработка первого/последнего кадра.

### 6. [P2] Validation усредняется по batch, а не по сегментам

`scripts/train_stage1.py:405-407`.

Последний неполный batch получает такой же вес, как полный. Например,
при val_max_segments=65, batch_size=64 один последний сегмент составляет
половину итоговой оценки. Это влияет на scheduler/best и меняет метрику
при смене batch size. Дефолтные 256 сегментов с batch 64/256 проблему
не проявляют, но CLI допускает другие значения и весь split.

Умножать batch mean loss на число сегментов и делить на суммарный count.

## Дополнительные проблемы продолжения запуска

- **Нет конфигурации в checkpoint.** Можно восстановить best_val_loss и
  scheduler, изменив delay, loss weights или validation split через CLI.
  Старое best сравнивается с другой метрикой. Сохранять config/manifest и
  запрещать несовместимый resume; для новой постановки использовать init-weights.
- **История не соответствует выбранному checkpoint.** JSON загружается
  целиком из output-dir, даже если resume идёт с более раннего best/epoch.
  Следующие записи дублируют эпохи, audio_seconds_seen стартует с будущего
  относительно checkpoint значения. Хранить историю в checkpoint либо
  обрезать и проверять её по epoch/run ID; журнал другого опыта не принимать.
- **Завершённый resume падает.** Если start_epoch>=args.epochs, цикл пуст,
  save_checkpoint(stage1_final.pt) обращается к ещё не определённой epoch.
  Нужна явная обработка «достигнуто требуемое число эпох».
- **Checkpoint по-прежнему неатомарный.** torch.save пишет прямо в best/final.
  JSON исправлен, но обрыв сохранения весов ещё может испортить best.
- **Fresh-run seed исчез.** Удалён прежний torch.manual_seed(0) перед
  созданием модели; локальный Generator(0) задаёт лишь validation subset.
  Для сопоставимого A/B нужны --seed, seed модели и отдельный generator
  DataLoader. Для точного resume также проверить влияние перезапуска
  persistent workers на потребление RNG.
- **Colab не обновлён.** Старый checkpoint stage1_final.pt в формате bare
  state_dict теперь отвергается --resume. Для миграции notebook должен
  явно использовать --init-weights и новый output-dir.
